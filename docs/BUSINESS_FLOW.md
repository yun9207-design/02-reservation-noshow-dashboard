# Business flow

## 1. 예약 확보
고객 요청을 받으면 서비스·담당자·시간을 입력합니다. 시스템은 영업시간, 담당자 제공 가능 서비스, 기존 예약과의 겹침을 검사합니다.

## 2. 예약금과 확정
정책상 예약금이 필요한 경우 `unpaid -> paid`를 거친 뒤 `requested -> confirmed`로 변경됩니다. 현재 앱의 결제는 모의 기록입니다.

## 3. 방문 결과
확정 예약은 `arrived -> completed` 또는 시간이 지난 뒤 `no_show`가 됩니다. 노쇼는 유예시간 이후에만 기록할 수 있습니다.

## 4. 취소
현재 실습 시각과 예약 시작 시각의 차이로 ‘정상 취소 / 늦은 취소’를 판단하고, 예약금 상태를 모의 환불 또는 차감으로 바꿉니다.

## 5. 빈자리 회복
취소 예약은 더 이상 일정을 점유하지 않습니다. 같은 서비스, 희망 시간, 담당자 조건을 만족하는 대기자를 찾습니다.

## 6. 제안과 홀드
대기자에게 취소 슬롯을 모의 제안하면 일정 시간 홀드 상태가 됩니다. 실제 메시지는 보내지 않습니다.

## 7. 수락 전 재검사
제안 후 다른 예약이 먼저 들어올 수 있으므로 수락 시 다시 겹침을 검사합니다. 안전하면 새 `waitlist` 출처 예약을 생성합니다.

## 8. 결과 측정
회복 예약의 서비스 금액 합계, 취소/노쇼 건수, 일정 점유율과 감사 이력을 계산합니다.
