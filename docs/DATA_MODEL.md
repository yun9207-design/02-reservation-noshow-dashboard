# Data model

- `Service`: 서비스명, 소요시간, 버퍼시간, 가격, 예약금
- `Staff`: 담당자와 제공 가능한 서비스
- `Customer`: 연락처(가상), 방문 수, 노쇼 수
- `Reservation`: 고객/서비스/담당자/시작·종료/예약 상태/예약금 상태/출처
- `WaitlistEntry`: 희망 서비스, 시간 범위, 선택 담당자, 제안 상태
- `WaitlistOffer`: 제안 슬롯, 발송 시각, 만료 시각, 수락/거절/만료 상태
- `Policy`: 취소 기준시간, 노쇼 유예, 제안 홀드, 영업시간, 예약금 정책
- `AuditEntry`: 각 상태 변경의 시간·대상·설명
- `AppState`: 위 자료와 실습용 가상 시각을 하나의 버전된 상태로 묶음

실제 백엔드에서는 이 구조를 그대로 한 JSON으로 저장하기보다 테이블/관계/권한 모델로 분리하는 것이 일반적입니다.
